# 专题　实时互动数字人：让屏幕里的老师活过来，能听懂问题、开口回答

> **一句话**：数字人分两种——"录像型"和"对话型"。本专题专讲后者：**学生提问，屏幕里的人当场开口回答**。主线方案是一个单文件网页，零成本、不联网、不用显卡，双击就能用。
>
> **本专题实测**：产物在 `digital_human/` 目录，自检数据全部来自真实运行（无 JS 报错、口型开合正常、投屏模式正常、自定义形象换装正常）。跟着做，**30 分钟**你能拥有第一个能回答问题数字人助教。

---

## 〇、先分清：你要的是哪一种数字人

很多老师兴冲冲去搜"数字人"，做完发现是个视频——它只会念稿，学生问什么它都不理。这两件事差别很大：

| | **录像型数字人** | **对话型数字人（本专题）** |
|---|---|---|
| 产物 | 一个 MP4 视频 | 一个网页 / 一个程序 |
| 学生提问 | 不理 | 当场回答 |
| 典型用途 | 微课讲解、校园播报、家长会致辞 | 课堂答疑、"复活"历史人物、英语陪练 |
| 做法 | 平台上传照片+文稿，导出视频 | 形象 + 语音 + 大脑三件套 |
| 成本 | 平台按条/按分钟收费 | **可以做到零成本** |

**判断标准只有一条**：学生能不能当场问它问题。能，才叫"互动数字人"。

## 一、四条路线，按门槛从低到高

| 路线 | 怎么做 | 形象 | 成本 | 要显卡吗 | 要联网吗 | 适合谁 |
|---|---|---|---|---|---|---|
| **① 平台直出** | 腾讯智影、即梦等平台上传照片和文稿 | 写实 | 按条/分钟计费 | 否 | 是 | 只要视频、不要求互动 |
| **② 云 SDK（魔珐星云）** | 一个 HTML，引一行 JS，填密钥 | 3D 超写实，有表情手势 | 0.5 积分/分钟（基础音色），新用户送额度 | 否 | 是 | 想要"电影级"效果、愿花小钱 |
| **③ 单文件自建（主线，实测）** | 本专题的 `数字人助教_单文件版.html` | 卡通内置 / 换成任意图片 | **0 元** | 否 | **否**（语音本地合成） | **绝大多数教师** |
| **④ 本地全能（Open-LLM-VTuber）** | `uv sync` 部署一个开源项目 | Live2D 二次元 | 0 元 | 否（用在线大模型时） | 可离线 | 想玩真·语音对话、愿意折腾 |

> 还有一条 **LiveTalking**（开源实时数字人引擎，支持 Wav2Lip / MuseTalk，可 WebRTC 推流、支持随时打断），但**需要独立显卡**，学校机房一般不具备，本专题只作了解，不展开。

**教师结论：先走路线 ③。** 它是唯一一条"零成本 + 能离线 + 课堂敢用"的路；等你确认课上真的需要，再上路线 ②换超写实形象，或路线 ④加语音对话。

## 二、主线实测：零成本单文件数字人

### 它到底是什么

一个 HTML 文件，三个部分拼起来：

```
形象（内置卡通，或你上传的任意一张正面图）
   ↓
嘴（随说话节奏开合的"口型引擎"）
   ↓
声音（浏览器自带的语音合成，本地生成，不联网、不花钱）
   ↓
大脑（课前录好的问答库；也可选接大模型）
```

**为什么不花钱**：语音用的是浏览器自带的合成能力（TTS），Windows 和 Edge/Chrome 里本来就装好了中文语音，不需要调任何接口。

### 实测数据（本机真实运行）

| 检查项 | 结果 |
|---|---|
| 页面 JS 报错 | 0 个 |
| 预设题库渲染 | 6 条，快捷标签 6 个 |
| 口型引擎 | 嘴部半径 3 → 11.1 → 3.2，完成一次完整开合 |
| 语音合成 | 成功触发，状态显示"说话中…" |
| 自定义形象 | 上传成功，嘴部标记到（50%, 44%） |
| 投屏模式 | 右侧面板隐藏、字号放大到 30px、Esc 正常退出 |
| 投屏下提问 | 输入"什么是光的折射？"→ 命中题库 → 数字人开口 |

### 第 1 步：拿到文件

文件路径：

```
教师版蓝皮书/digital_human/数字人助教_单文件版.html
```

**双击用 Chrome 或 Edge 打开**（别用 IE，也别用微信内置浏览器）。

### 第 2 步：先让它开口

点右上角 **`▶ 试说一句`**。听到声音、看到嘴巴动，就说明通了。

- 没声音？看左下角"声音与口型"卡里的音色列表。列表为空，说明系统没装中文语音包：Windows 到「设置 → 时间和语言 → 语音」添加中文语音。
- 想调声音：语速、音调两个滑块直接拖。讲话太快学生听不清，语速建议 **0.9**。

### 第 3 步：换成你自己的形象（关键一步）

内置的是卡通老师。想换成"你自己"、"你们学校的卡通吉祥物"，或者"李白""韩非子"：

1. 点 **`选择文件`**，选一张**正面、脸部清晰**的图（自己的照片、AI 生成的形象都行）；也可以**直接把图片拖进画面**。
2. 图上会出现一行提示：**点击画面上嘴巴的位置**——在嘴巴正中点一下。
3. 点完会显示"嘴部已标记（50%, 44%）"。位置不准就再点一次。
4. 嘴太大/太小：拖"嘴部大小"滑块。

> 这一页文件夹里已放了一张实测用的示例形象 `示例形象_女教师.png`（AI 生成），你可以直接拿来练手。
>
> **换形象的提示词**（想用 AI 造一个专属形象时，把这段话发给 WorkBuddy 或任意生图工具）：
>
> ```
> 扁平插画风格，正面上半身肖像，一位亲切的中国中学教师，
> 面带微笑、嘴巴闭合、五官端正对称居中，纯浅灰色纯色背景，
> 无文字无水印，卡通矢量插画。
> ```

### 第 4 步：课前录题库（课堂好不好用，全看这一步）

这是整套方案里**最值钱**的一步。

课上学生会问什么，你比大模型清楚。课前花 15 分钟把问题和答案录进去：

- 在右侧"预设问答库"下方填「问题」和「答案」，点 `添加`。
- 答案就是**数字人要念的台词**。写成口语，别写成书面语——它是"说"出来的。
- 录好后，点每条右边的 **`▶ 说`** 就能让数字人开口。
- 题库存在本机浏览器里；换电脑用 `导出题库 JSON` / `导入题库 JSON` 带走。

**为什么强烈建议用题库，而不是全交给大模型**：

| | 预设题库 | 大模型临场回答 |
|---|---|---|
| 准确性 | 你把关，**不会答错** | 可能答错，理科尤其危险 |
| 速度 | 点了就说，**零延迟** | 要等 2–5 秒 |
| 断网 | 照常用 | 用不了 |
| 备课成本 | 15 分钟 | 0 |

**课堂主力用题库，大模型只当补充。**

### 第 5 步：上课投屏

点 **`⛶ 投屏模式`**：

- 右侧所有面板收起，只剩数字人和大字幕（字号自动放大到 30px）；
- 底部留一条输入框，你打字提问，回车，数字人开口；
- 按钮平时隐身（鼠标移过去才出现），学生在屏幕上只看得到数字人，不会被界面分散注意力；
- 按 **Esc** 退出。

### 三种回答问题的方式（按需要选）

1. **题库命中**（默认）：输入的问题和题库里某条对上，直接开口。离线、零延迟。
2. **粘贴答案**：题库里没有的问题，你从 DeepSeek、WorkBuddy 等工具复制答案，粘进"数字人要说的话"框，点 `开口说`。**零配置、零风险，强烈推荐**。
3. **接大模型**（可选）：填接口地址 + API Key + 角色设定，学生提问自动作答。
   - 密钥只存在你这台电脑的浏览器里；
   - 部分接口从网页直连会被浏览器拦截（CORS），报错就退回方式 2，课堂效果一样；
   - **角色设定**这一栏是灵魂。比如语文课上写：

```
你是战国时期的韩非子，用讲故事的方式回答初中生的问题，
每次回答控制在 80 字以内，口语化，可以反问学生一句。
```

## 三、课堂怎么用：四个已经有人做出来的场景

下面四个场景都来自真实学校实践，不是设想：

| 场景 | 别人的做法 | 你怎么落地 |
|---|---|---|
| **AI 助教答疑问** | 北京四中雄安校区放了一台"小优老师"数字人一体机，学生围着问"降落伞包含哪些部分"，课堂互动从每节课几次涨到几十次 | 你的数字人放投影上，讲到重难点时让它"接答"，你腾出手去巡堂 |
| **"复活"历史人物** | 成都棕北中学物理课上让帕斯卡本人讲解大气压强；桥头镇小学语文课让"韩非子"带学生逛寓言博物馆 | 换一张人物图 + 一段角色设定，课本里的人物就能开口 |
| **英语口语陪练** | 遵义试点学校用虚拟数字人做场景化对话，学生开口练，AI 实时反馈 | 英语老师把常用对话录进题库，数字人当"对话对象" |
| **跨校同步课堂** | 金华江滨小学用 AI 数字人"后羿"当科学助教，三所学校同时上课，隔空提问 | 数字人画面投出去，远端学生同样能提问 |

**通用流程（备课 20 分钟）**：

```
选一节有重难点的课
  → 想清楚学生最可能问的 5–8 个问题
  → 写成口语答案，录进题库
  → 换上和课文相关的形象（作者 / 科学家 / 课文人物）
  → 课上：讲到关键处 → 让学生提问 → 点标签 → 数字人开口
```

**让 WorkBuddy 帮你写题库的提示词**（直接复制）：

```
我在准备《XXX》这一课，要做一个数字人助教。
请帮我想：初中生/小学生学这一课时，最可能提出的 8 个问题，
每个问题配一段 60–80 字的口语化回答（要像老师在课堂上讲话的语气，
不要书面语，可以有语气词）。用表格给我：问题 | 答案。
另外给我一段这个角色的"人设提示词"，用来约束它的回答风格。
```

## 四、想要超写实 3D：魔珐星云路线

如果你觉得卡通形象"不够震撼"，想让屏幕里站一个像真人的 3D 老师，走这条路。

**代价**：按用量付费（实时驱动 0.5 积分/分钟，基础音色；更贵的音色 2 积分/分钟），新用户注册送额度，够你试。

**做法**（一个 HTML，核心不到 50 行）：

```html
<div id="sdk" style="width:800px;height:600px"></div>
<script src="https://<官方 SDK 地址>/XmovAvatar.js"></script>
<script>
const LiteSDK = new XmovAvatar({
  containerId: '#sdk',
  appId: '你的AppID',
  appSecret: '你的AppSecret',
  gatewayServer: 'https://nebula-agent.xingyun3d.com/user/v1/ttsa/session',
  onStateChange: s => console.log('状态', s)
});

await LiteSDK.init({
  onDownloadProgress: p => console.log('加载 ' + p + '%'),
  onError: e => console.error('失败', e)
});

// 让它说话（还能在文本里嵌动作指令）
LiteSDK.speak('同学们好，今天我们学大气压强。', true, true);
</script>
```

**流程**：注册账号 → 创建应用 → 选形象和音色 → 拿到 AppID / AppSecret → 填进上面代码 → 接你自己的大模型（DeepSeek、通义、豆包都行）。

**三个坑**（别人踩过的）：

1. **页面必须是 `localhost` 或 HTTPS**。直接双击打开本地 HTML（file://）或 HTTP+IP 访问，会失败。本机试用就起个本地服务，或用 `https` 托管。
2. **容器必须有明确宽高**，否则数字人显示不全。
3. **免费额度有限**，先算好一节课大概几分钟，别上到一半断粮。

## 五、想要"能听懂说话"：本地部署路线

前面所有方案，学生提问都得打字。想让学生**直接对着麦克风说话**，数字人听着回答，有两条路：

**路 A：借系统输入（零成本，强烈推荐）**

键盘按 **`Win + H`**，打开 Windows 自带语音听写，对着麦克风说，文字直接进输入框，回车即可。**不用装任何东西，也不需要联网到国外服务器。**

> ⚠️ 一个重要的坑：网上很多教程教你在网页里用浏览器自带语音识别（`webkitSpeechRecognition`），**在国内基本用不了**——它要把音频传到谷歌服务器，普通网络环境下会直接报 network 错误。别在这上面浪费时间。

**路 B：本地部署 Open-LLM-VTuber（免费、可离线、功能最全）**

一个开源项目，把大模型、语音识别、语音合成和 Live2D 形象串起来，能随时打断，支持摄像头和屏幕共享。

```bash
git clone https://github.com/Open-LLM-VTuber/Open-LLM-VTuber
cd Open-LLM-VTuber
uv sync                                   # 自动装依赖
cp config_templates/conf.default.yaml conf.yaml
uv run run_server.py                      # 启动
# 浏览器打开 http://localhost:12393
```

**代价**：Python 3.10–3.13、磁盘留 10GB（要下语音模型）、首次部署半小时左右。适合学校机房有一台固定机器、或你自己愿意折腾的情况。它默认用 `sherpa-onnx` 做本地语音识别，**不依赖国外服务，国内可用**。

## 六、坑与红线

**技术坑**

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 点了没声音 | 系统没装中文语音包 | Windows「设置 → 时间和语言 → 语音」添加 |
| 网页语音识别用不了 | 走谷歌云，国内不通 | 用 `Win+H` 系统听写，或用题库 |
| 嘴的位置不对 | 标记点偏了 | 在画面上重新点一次嘴巴正中 |
| 接大模型报 CORS | 浏览器拦截跨域 | 改用"粘贴答案"方式 |
| 投屏后找不到按钮 | 按钮设计成隐身 | 鼠标移到输入框上就出来，Esc 退出投屏 |

**教学红线（和所有 AI 工具一样）**

1. **知识点必须你把关。** 用题库的最大好处就是答案是你写的，不会错。一旦接大模型，它说的每一个知识点你都要先验一遍，理科尤其小心。
2. **别把学生信息喂进去。** 姓名、成绩、家庭情况、心理测评，一律不进任何联网服务。
3. **别让学生以为它说的都对。** 第一次用就要跟学生讲清楚：这是 AI 助教，它可能答错，发现不对就举手。
4. **它是助教，不是替身。** 数字人适合做"重难点重复讲""人物角色扮演""陪练"，不适合替代你和学生的真实互动。北京四中的经验值得记住：数字人把互动次数从几次提到几十次，但**组织和引导还是老师在做的**。
