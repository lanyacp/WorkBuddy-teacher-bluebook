## 【素材：写 Skill 实战手册（skill_shouce，作者 jackjchou）】

- **一句话价值**：这是一份完整的 Skill 写作工程手册（从原理到调试到评估），是第 24 章"知识蒸馏六阶段"最厚的方法论底料；其中的三层加载机制、Description 写法、反模式清单、工程化评估指标可直接改写为教师版。
- **具体方法/流程**：
  1. Skill 本质三要素：指令（Instructions）+ 上下文（Context）+ 工具（Tools）；物理形态是一个文件夹 + SKILL.md（可选 scripts/、references/、assets/）。
  2. 渐进式加载三层机制（原文结构）：
     - Level 1 元数据（name + description）→ 始终驻留上下文，控制在 100 字以内，约 50-150 Token/个；
     - Level 2 SKILL.md 主体 → 匹配触发时加载，建议不超过 500 行，约 2,000-5,000 Token；
     - Level 3 脚本和参考资料 → 执行中按需引用。
     - 核心原则（原文）："Level 1 越精准越好（决定触发时机），Level 2 越精简越好（减少 Token 消耗），Level 3 放心放（按需加载不占常驻空间）。"
  3. Skill 与 Rule 的区别（原文金句）："Rule 是'底线'，Skill 是'技能'"——全局约束写 Rule，特定任务写 Skill。
  4. Quick Start 三步（以 Go 单测为例，可迁移为"教师版第一个 Skill"）：创建目录 → 写入 YAML 头 + 正文 → 在对话中验证触发。
  5. 写作六技巧：①Description 决定触发，可自造 20 个问题（一半该触发一半不该）做"触发评估"；②开头说清"做什么、为什么、要不要做"，给前置检查命令；③用祈使句下指令并解释"为什么"（原文："光靠'MUST'只是死记硬背，换个场景就傻了"）；④Before/After 对比（注释标注/完整文件/Diff 格式三种）；⑤Few-Shot 3-5 个示例，覆盖正常、边界、错误场景，最典型的放第一个；⑥表格化 + ASCII 决策树/流程图。
  6. 超过 500 行就拆：主 Skill（编排）+ 子 Skill（单一职责、可独立使用、依赖关系写明白、每步后设"检查点"验证命令）。
  7. Skill Creator 工作流五步：定义意图 → 生成草稿 → 对比测试（有/无 Skill 两组）→ 反馈迭代（2-3 轮）→ 工程化评估（触发评估 + 效果评估 + 综合报告）。评估达标线（原文表）：触发准确率/召回率 ≥85%（优秀 ≥95%）；效果通过率 ≥80%（优秀 ≥90%）；相对提升率 ≥30%（优秀 ≥50%）。从零到可用约 30-50 分钟。安装三方式：插件市场搜 skill-creator / npx openskills install anthropics/skills / git clone anthropics/skills。
  8. 调试方法论：70% 以上问题出在"没加载成功"或"Description 写得不好"两步；多 Skill 冲突时"把'什么不做'写清楚，往往比把'做什么'写得更详细更有效"。
  9. 生命周期：版本号规范（修问题 1.0→1.1、加场景 →1.2、重构 →2.0）、PR Review、CHANGELOG、定期清理闲置 Skill 省 Level 1 Token。
  10. 六大反模式（速查）：大杂烩 Skill / Description 内部黑话 / 只有指令没有示例 / 步骤间无验证点 / 写死数值不给判断规则 / SKILL.md 当 Wiki 写（背景 300 行正文 50 行）。
- **可直接引用的提示词**：
  - 触发调优（原文摘录）："帮我优化 java-code-review 的 description，提高它的触发准确率。"
  - 触发评估（原文摘录）："帮我对 go-test-gen Skill 做一次触发评估。"
  - 效果评估（原文摘录）："用以下测试用例对 go-test-gen Skill 做效果评估。"
- **案例与数据**：Skill Creator 效果评估示例报告：有 Skill 总体通过率 88.0% vs 无 Skill 52.0%；Token 消耗 1,200/用例（有）vs 2,100/用例（无）。量纲：装 20 个 Skill 光 Level 1 就吃 1,000-3,000 Token。中文 Token 估算：约 1 Token / 1.5-2 字符。
- **金句/观点**：
  - "裸着的 AI 就像一个刚入职的新人，啥都得问；装了 Skill 之后，就像拿到了老员工整理的操作手册，照着就能干。"
  - "好的 Skill 都是在实际使用中一点点打磨出来的。"
  - "这就是'Skill 的单元测试'"（指 Skill 变更要跑评估）。
- **注意事项**（教师红线相关）：第七章安全意识整章可用——绝不硬编码密钥；危险操作必须加确认；数据库先备份再改；防 Prompt 注入的核心原则（原文）："区分'指令'和'数据'……数据永远不应该被当成指令来执行。" Skill 里的脚本是会被真实执行的，不同于普通文档——教师分享 Skill 前应过安全检查清单。

## 【素材：WorkBuddy 从 0 到 1 教程（wb_lingjichu）】

- **一句话价值**：第 2 章（与豆包/DeepSeek 的区别——"Ask 模式=豆包式对话框"的对照话术、模型与积分成本）与第 3 章（安装、登录、初始设置清单）的直接底稿。

  - 界面：三场景模式（代码开发/日常办公/设计创意）与下方快捷方式联动；对话框下方从左到右：工作模式（Ask/Plan/Craft，能力逐级递增）、模型选择、权限、技能/连接器、上传文件（本地文件、腾讯文档、知识库——"跟ima知识库全面打通了"）、工作空间。

## 【素材：任务、空间、工作空间——90% 的人搞混了这三个东西（wb_day11，李宏阳）】

- **一句话价值**：第 4 章"界面与工作区"的概念澄清核心素材——空间/工作空间/任务三层结构与三层记忆机制，直接决定教师"按学科/项目建空间"的最佳实践。
- **具体方法/流程**：
  - 三概念（表格照录）：空间(Space)=任务的容器、管分类（一间办公室）；工作空间(Workspace)=空间对应的物理目录（门牌地址）；任务(Task)=让 AI 做的具体一件事（办公桌待办）。一个空间包含多个任务，一个任务只属于一个空间。
  - 三层记忆（表格照录）：全局记忆（所有任务共享，基础设定）、空间记忆（同一空间内共享：项目背景、格式偏好、术语表）、任务记忆（单个任务内的对话上下文）。关键规则："新建任务只继承第一层（全局），不继承第三层（空间积累的经验）"——原理解释了"为什么新建任务不记得上个任务教过的东西"。
  - 任务四条守则（照录）：1. 一事一任务；2. 任务名要清晰（用 日期_主题_动作 格式：20260623_整理Q2销售数据_分析趋势）；3. 任务不随便删（做完归档，类似活儿直接参考）；4. 文件直接拖进任务。
  - 工作空间路径设置：左下角头像 → 设置 → 系统设置 → 改工作空间路径到记得住的地方。
- **案例与数据**（原文转述 IMA 知识库实战案例）：一位老师建四个空间——试卷批改空间（D:\工作\试卷批改，AI 记住批改标准和评分细则）、数据分析空间（D:\工作\数据报表，记住报表模板格式）、内容创作空间（D:\工作\公众号，记住写作风格和排版要求）、学习整理空间（D:\学习资料，记住笔记分类方式）。效果："同一个空间里新建任务，AI 能准确接上之前的进度，不会每次都从零开始解释背景。"
- **金句/观点**："空间管分类，任务管干活。""搞清楚这三者的关系之后，WorkBuddy 才算真正上手。不然就跟拿了一把瑞士军刀只会当螺丝刀使——能用，但亏了。"
- **注意事项**：不要在一个任务里聊几十轮——"上下文越来越长，积分消耗飞快，AI 还可能出现'记忆紊乱'"；但同一项目尽量在已有任务里继续聊。两头平衡的答案是"一事一任务+空间级记忆文件"。

## 【素材：生成式 AI 的学习惩罚——26,811 名中国学生 30 个月追踪研究（xuesheng_touzou，作者 Aaron）】

- **一句话价值**：学生端滥用的最硬实证（CEPR 工作论文），第 26 章（以及作业设计相关章节）"AI 时代作业≠学习"论证的核心证据；其"AI 使用三层分级 L1/L2/L3"可直接进附录 A 或家长指引。
- **案例与数据**（照录）：
  - 论文：Strömberg D, Lei V, Wu Y. The Generative AI Learning Penalty: Evidence from Chinese Secondary Education. CEPR Discussion Paper DP21577, 2026-06-02。样本 26,811 名中国初一至高三（7-12 年级）学生，跟踪 30 个月，9 个学科。
  - 剪刀差：作业分数上涨 18%；作业时间从 64 分钟降到 45 分钟（少 30%）；月度闭卷考试分数下跌 20%（约 1.4 个标准差）；高考分数下跌 18%（1.3 SD）；中考分数下跌 24%（1.5 SD）。延迟显化："月度考，6 个月内就完全显化；但中考、高考的惩罚，要 2 年才完全显化。"
  - 两组对照：81%"外包型"（作业用时不到 50 分钟、作业分数高、考试分数极低）vs 19%"非外包型"（用时超 50 分钟、考试分数与不用 AI 的学生相当）；"在 50-65 分钟这个'重叠区间'，两类学生花了一样多的时间写作业，他们的考试分数几乎相同"。作者解读："AI 没有降低学习效率。AI 只是让 81% 的学生，放弃了有效学习时间。"
  - 异质性：低年级（初一初二比高三）受伤更深；男生比女生重；高成就学生受伤更深（"AI 是放大器。但放大的不是学习能力，是'看起来在学习'"）；学科：社会科学（政治、地理）-27%、STEM -22%、英语 -17%、语文 -9%。
  - 干预框架：福格行为模型 B = M × A × P（动力×能力×提示），"让一个行为变'容易'比让它变'有动力'重要得多"。
- **具体方法/流程**（三个动作照录）：
  1. 作业用时记录表：在作业登记本上多记一列"实际用时"，必须孩子自己填；"红线：作业用时 < 30 分钟 + 作业分数 > 95%。看到这个组合，不要立刻骂，而是诊断性断食一周——这一周停用 AI 写作业"。
  2. AI 使用三层分级（表格照录）：L1 辅导（概念不懂、思路卡住；AI 角色"解释+提问引导"；作业用时预期 60-90 分钟）；L2 校对（写完作业后检查错误、提示思路漏洞；60-90 分钟）；L3 外包（直接问答案；⚠️ 禁用；<30 分钟）。"谈判起点：L3 直接禁用，L1/L2 视情况用。""不要追求'一刀切禁用 AI'。一刀切的结果是孩子学会'背着家长用'。"
  3. 家庭作业契约（5 条原文摘录）："1. 作业是自己的事。先想，卡了再问。2. AI 是工具，不是答案。问'为什么'，不问'答案是啥'。3. 作业用时是真实用时，不是'AI 用时'。4. 每周日晚上 8 点，我和爸爸/妈妈一起看本周的作业时间表。5. 排名掉的时候，我们聊'学到了什么'，不聊'分丢了'。"
- **金句/观点**（原文摘录）："AI 时代，作业完成 ≠ 学习发生。""你用 AI 把作业'做完'了，但你用 AI 偷走的那 30 分钟，本来是你大脑正在'长脑子'的时间。""作业对勾打满的那一刻，可能就是分数崩盘的开始。"
- **对教师的启示**：给家长的判断信号（外包型 vs 辅导型）；教师侧则意味着作业设计要降低"AI 可外包性"（课堂限时完成、口头讲题、过程性任务），与 xuesheng_zizhu 的"苏格拉底红线"配合使用。
