# 专题　教师用 WorkBuddy 开发工具：从一句抱怨到一个能装的插件（路径助手全程实录）

> **一句话**：不是让 AI 帮你做一次课件，而是让 AI 帮你做一个「以后每次做课件都能用」的小工具。一位非程序员教师，把「WPS 路径动画对不准」这个每次要磨二十分钟的老问题，做成了能安装、能自检、能讲清、能开源的加载项。
>
> **本专题是实测记录**：全部数字、命令、报错与踩坑来自 2026-11-06 至 11-12 在本机的真实开发（Windows 11 / WPS Office 12.1.0.29690 / Node 22.22.2 / WorkBuddy）。成品是**路径助手 v1.3.2**，已在本机 WPS 演示里加载出「路径助手」选项卡，并开源到 Gitee。
>
> **和全书其他专题的分工**：第 24 章讲「把做过 3 次的流程沉淀成 Skill」，专题 09–15 讲「用 WorkBuddy 做出课件 / 视频 / 3D 模型」——这些都在**用工具产出成品**。本专题讲的是**做出一个工具本身**：它装进 WPS，有版本号、有安装脚本、有自检、有文档、有文章和视频、有仓库。是从「会用」到「能造」的那一步。
>
> **读法**：只想判断值不值得做 → 读〇、一；想照着做 → 读二、三、附录 A；要给教研组讲，或自己正卡在某个坑里 → 读四、五、七。

## 〇、三分钟看懂

| 项目 | 说明 |
|---|---|
| **能做什么** | 给 WPS 演示加一个选项卡，把「图形中心从 A 精确移动到 B」写成路径动画，支持直线、抛物线、圆弧、航点、描迹五种形态 |
| **靠什么做** | 让 WorkBuddy 读加载项结构、写 JS/HTML/XML、写自检、写安装脚本、写文档、做配图与视频 |
| **做出来的东西** | 一个双击 `install.bat` 就能装的加载项——**不是提示词，不是模板，不是一次性产物** |
| **前提** | Windows + WPS 演示；Node 用于跑自检；不需要会写 JS，但要能判断「这样算不算做对了」 |
| **本次实测规模** | 27 个源文件 / 4175 行 / **107 项静态自检全绿** / 5 种路径形态 |
| **成品落点** | 本机 WPS 功能区出现「路径助手」选项卡；Gitee 公开仓库 `lanyacp/lujingzhusou`，commit `5250641` |
| **配套产物** | 定稿文章 1 篇 + 排版/纯文字文件 5 份、配图 11 张、真实截图 3 张、封面 3 张、解说视频 51.29 秒（18 条字幕） |

### 三条路线，先选对再动手

| 路线 | 做法 | 下次遇到同样的事 | 适合 |
|---|---|---|---|
| A | 每次让 AI 帮你做一次 | 重新描述一遍 | 一学期一两次的偶发任务 |
| B | 把流程写成 Skill / 提示词模板 | 复制模板改参数 | 流程固定，但不必装进软件 |
| C | **做成能装的小工具** | 点一下按钮 | 高频、要求精确、还要给别人用 |

> **一句话纪律**：不是所有烦事都值得做成工具。**一学期用不到三次的，写个提示词就够了。** 做成工具要多付三笔成本：安装维护、版本兼容、给别人讲清楚。

### 三问判断（先回答，再开工）

| 问题 | 路径助手的答案 |
|---|---|

## 一、把抱怨翻译成一个可验证的需求

真实场景：WPS / PPT 的路径动画是**按图形中心点**移动的，可编辑界面里中心看不见、也没有参照物。要让三角形平移到与另一个重合，只能凭感觉拖路径；拖完播放一看，歪了；再调，再歪。一个动画调二十分钟是常事。

| 原始说法 | 问题在哪 | 改成 |
|---|---|---|
| 「路径动画老对不准」 | 没法验收 | 「选中图形，点生成，播放时图形中心精确落在 B 点」 |
| 「要精确」 | 没有标准 | 「位移写入 `MotionEffect.Path`，回读值等于归一化坐标」 |
| 「最好还能走曲线」 | 范围失控 | 「先做直线；曲线列为第二阶段」 |

> **人要确认什么**：「精确」到底指什么。本例定为**坐标级**，不是「看起来齐」。这一个定义，决定了后面整套实现方式、自检怎么写、文案敢怎么写。

**可复制提示词 P1（需求澄清）**

```
我是教师，不是程序员。我在（软件名）里遇到这样一个问题：
（描述场景，写清现在怎么操作、哪一步最费时间、错的时候错成什么样）。

先别写代码。帮我做三件事：
1. 把这段抱怨改写成一句「可验证的需求」，必须包含：选中什么、点什么、
   播放／运行时应该看到什么；
2. 指出这句话里哪些词是模糊的（例如「精确」「快」「好用」），
   逐个给出可测量的替代说法；
3. 列出最小版本和第二阶段，明确这次只做最小版本。

最后反问我一句：这个验收动作对不对。等我确认再往下走。
```

## 二、六个阶段：WorkBuddy 做什么，人必须确认什么

| 阶段 | WorkBuddy 做什么 | 人必须确认什么 | 本例产物 |
|---|---|---|---|
| ① 需求 | 把抱怨改成可验证需求 | 「精确」的定义、验收动作 | 一句话需求 |
| ② 探路 | 写**最小验证探针**，只验「能不能写、能不能回读」 | 探针结论是否通过 | `tools/test-results/latest.json` |
| ③ 本体 | 写加载项入口、功能区、核心逻辑、任务窗格 | 按钮叫什么、流程分几步 | `index.html`／`main.js`／`ribbon.xml`／`js/`／`ui/`／`images/` |
| ④ 自检 | 写一条命令跑完的静态自检 + 状态机模拟 | 哪些分支必须被测到 | `tools/static-check.js`，107 项 |
| ⑤ 安装 | 写安装／卸载脚本，合并注册项 | 会不会覆盖别人已有的加载项 | `install.bat`／`uninstall.bat`／`merge-publish.ps1` |
| ⑥ 讲清与交付 | 文章、配图、封面、解说视频、开源仓库 | 事实有没有说错、能不能公开 | 见第六节产物清单 |

### ② 探路这一步不能省

不要一上来就写整个插件。先让 WorkBuddy 做一件最小的事：**新建一个临时演示文稿和一个临时形状，给形状加路径动画，把位移写进 `MotionEffect.Path`，再回读出来，跑完自动清理。**

本例的历史实测存档里，回读值是 `M 0 0 L 0.250000 0.125000 E`——字符串与写入值一致，才敢往下写插件。这一步同时逼出三条后来写进 README 的事实：

- `MotionEffect.Path` 可读可写，是唯一可靠的路径写入方式；
- `MotionEffect.FromX / ToX` 写入会被**静默忽略**（回读恒为默认值）；
- 时间线每次变更后 `Sequence / Effect` 引用会失效，每次操作前要重新获取。

> **一句话**：探针不通就停。AI 很擅长把不通的路写成看起来很完整的代码。

### ③ 本体：文件结构比代码重要

| 文件 | 管什么 |
|---|---|
| `index.html` / `main.js` / `ribbon.xml` | 加载项入口、功能区定义、四个按钮 |
| `js/core.js` | 图形选择、标记、预览线、路径数学、三级策略链、API 诊断 |
| `js/taskpane.js` + `ui/taskpane.html` | 任务窗格状态机：选中图形 → 放标记 → 拖 B 点 → 生成 |
| `js/enums.js` / `js/util.js` | 数值枚举与工具函数 |
| `images/*.svg` | 功能区按钮图标（**属于程序资源，别当配图删掉**） |
| `probe/` | 免安装、可粘进 WPS 宏编辑器的独立验证脚本 |

### ④ 自检：让 AI 给自己出题

`node tools/static-check.js` 一条命令跑完 107 项，覆盖：

- ribbon.xml 良构、回调函数与按钮 id 一一对应、图标文件存在；
- 所有 JS 语法、入口引用、任务窗格 DOM 元素齐全；
- 状态机 T1–T20：选中新图形、冷却期不误重启、B 标记误删重生、跨页跨文稿重置、僵尸图形保护；
- 数学正确性：C→D 位移、抛物线／圆弧的贝塞尔串、航点折线与平滑、描迹多段折线；
- 自动吸附的开启／关闭、C/D 标记点模式切换。

> **人要确认什么**：不是「全绿」三个字，而是**哪些分支被测了**。本例把最容易出错的「生成后同图形不自动重启」「旧页标记清理」「吸附不重复触发」都单独列了测试项。

### ⑤ 安装：合并，不要覆盖

`install.bat` 把文件复制到 `%APPDATA%\kingsoft\wps\jsaddons\ABPathHelper_1.0.0\`，再用 `merge-publish.ps1` **合并**一行注册项到 `publish.xml`——学校电脑上常装着别的加载项，直接覆盖会把人家弄坏。卸载同理，只移除自己那一行。

> **一个必须写进文档的坑**：安装完要**完全退出 WPS**（含托盘图标和后台进程）再重开，选项卡才会出现。这一条不写，用户会以为插件坏了。

### ⑥ 一个工具不算做完

别人装不上、看不懂、不敢用，就不算成品。本例把「讲清楚」也当成开发阶段：定稿文章、配图、封面、51 秒解说视频、开源仓库，都是工具的组成部分。**尤其要注意：解说词和文档里的每一句功能描述，都要回头查代码核实**（见踩坑第 19 条）。

## 三、六条可直接复制的提示词

**P2　最小验证探针（阶段②）**

```
不要开始写插件。先做一个最小验证：用一段独立脚本，验证
「（软件）里能不能给一个形状加上（目标效果），把参数写进去，再回读出来」。
要求：
① 新建临时文档／临时形状，跑完自动清理；
② 把写入值和回读值都打印出来；
③ 失败时明确报是哪一步不支持、报错原文是什么；
④ 结果写进一个 json 存档。
我只要这一件事的结论。通过了我再决定写不写插件。
```

**P3　写工具本体（阶段③）**

```
按下面结构生成（工具名）的最小可用版本，不要加我没要求的功能：
入口文件、功能区定义、核心逻辑、任务窗格 UI、图标、独立验证脚本，共六类。
约束：
① 每个辅助对象用统一前缀命名，方便一键清理；
② 所有对外操作先做能力检测，失败要有明确提示，不要静默吞错；
③ 关键计算写成纯函数，方便单独测；
④ 先给出文件清单和每个文件的职责，等我确认再写具体实现。
```

**P4　写自检（阶段④）**

```
给上面的工具写一条命令能跑完的自检脚本，不许依赖第三方包。
至少要覆盖四类：文件引用完整性、配置文件良构与回调对应、
所有业务状态分支、关键数学计算的结果比对。
每项输出 [OK] / [FAIL] 和中文说明，末尾给总数。
另外告诉我：哪些分支你没测到、为什么。
```

**P5　写安装与排障文档（阶段⑤）**

```
写安装／卸载脚本和 README 的安装、故障排查两节。
硬要求：
① 注册文件必须「合并」写入，保留已有其他加载项条目，不许整文件覆盖；
② 卸载只移除自己那一行；
③ 故障排查至少 6 条，按「现象 → 原因 → 怎么办」写，
   包含「完全退出软件再重开」「版本自动更新后首次启动要点完提示框」这类
   只有真踩过才知道的坑；
④ 明确写出哪些目录名是注册 ID、不是软件版本号，不要让用户手改。
```

**P6　写传播材料（阶段⑥）**

```
按教师视角写一篇介绍文章：痛点场景开场、结论先行、短段落、口语化，
功能分节 + 表格 + 安装三步 + 常见问题 + 金句收尾，不写营销腔。
再给出：① 每个插图位置的截图清单（截哪个界面、画面里必须出现什么）；
② 各平台封面尺寸与文案；③ 一段按功能点分镜的解说词。
所有功能描述以代码实际实现为准，不确定的地方标出来问我，不要替我猜。
```

**P7　开源前审查**

```
准备把这个项目开源。先别提交，做一次审查：
① 起草 .gitignore，排除私人工作记录、内部计划、文章与配图、安装包、
   测试中间产物、任何凭据文件；
② 检查版本号在 package.json / 注册项 / UI / 安装包里是否一致，
   不一致的指出哪一个是注册 ID、不该改；
③ 检查 README 的「已知限制」有没有和已实现功能矛盾；
④ 建议一个许可证并说明理由；
⑤ 列出将纳入仓库的文件清单，等我确认。
```

## 四、20 条踩坑清单（全部来自本次实测）

### 技术组

| # | 现象 | 原因 | 怎么办 |
|---|---|---|---|
| 1 | PowerShell 的 `Add-Type`、`New-Object -ComObject` 被安全策略拦截 | 本机禁止运行时编译与 COM 实例化 | **不要换 Python win32com 之类等价方式绕过**。改走不碰 COM 的路：静态自检、`PIL.ImageGrab` 截屏、HTML 渲染出图 |
| 2 | 写入 `FromX/ToX` 后回读恒为默认值 | WPS 静默忽略该属性 | 只写 `MotionEffect.Path` |
| 3 | 时间线改一次，后面的动画对象就失效 | COM 引用过期 | 每次操作前重新取 `TimeLine.MainSequence` |
| 4 | 版本号四处打架：`package.json` 1.0.3 / 注册目录 1.0.0 / UI 1.3.2 / 安装包 1.3.2 | 注册 ID 与软件版本混用 | 统一软件版本，并在 README 写明「1.0.0 是加载项注册 ID，不要手改」 |
| 5 | README「已知限制」还写着「路径为直线」，实际已有五种形态 | 文档没跟着功能走 | 每次加功能回头改「已知限制」，比没文档更误导入的是过时的文档 |
| 6 | 测出来一切正常，用户装的却没新功能 | `%APPDATA%` 里已安装副本 10 个文件全部落后于源码 | 改完重装一次；交付前用哈希比对源码与安装副本 |
| 7 | 安装包解压后目录名乱码、`unzip -l` 报警告 | 包内用反斜杠路径 + GBK 中文目录名 | 用 Python `zipfile` 逐字节比对；提醒用户用 Windows 自带解压 |

### 环境组

| # | 现象 | 原因 | 怎么办 |
|---|---|---|---|
| 8 | WPS 里看不到新选项卡，却弹出「加载项 ABPathHelper 已被修改，是否继续加载？」 | 加载项指纹变化，等待确认 | 点「确定」后才加载；文档要写这一步 |
| 9 | WPS 自动更新后插件不加载 | 首次运行的隐私协议／默认软件提示框阻塞加载项 | 人工打开一次点完所有提示，再重启 |
| 10 | 反复启动演示程序，累积多个「演示文稿」标签并切回首页，截图里带出最近文档列表 | WPS 复用同一主窗口 | 只截功能区横条区域；**截屏前先想清楚画面里有没有隐私** |
| 11 | `git-credential-manager.exe store: No such file or directory` | 全局凭据助手指向已失效路径 | push 本次仍成功，但要提醒下次可能需重新登录 |

### 发布组

| # | 现象 | 原因 | 怎么办 |
|---|---|---|---|
| 12 | 排版 HTML 第一次校验报 86 处「中文文本未被 span leaf 包裹」 | 关键词下划线把段落切成多段后，非关键词文字漏了包裹 | 每个文本片段都单独包；用校验脚本跑到 **0 ERROR / 0 WARNING** 再交付 |
| 13 | 半角逗号、英文直引号触发 warning | 公众号编辑器会自动「纠正」 | 生成时直接写中文全角标点，别事后替换 |
| 14 | 草稿箱里图片全丢 | HTML 里是本地相对路径 | 先把图片传到素材库换线上 URL，再替换 `src` |
| 15 | 公众号 API 的 IP 白名单配了也没用 | 公网动态 IP，每次都变 | **别硬配凭据**。改走复制粘贴／扫码推送，并把这条写进项目约定，以后不再建议配白名单 |
| 16 | 封面上传后被裁掉关键信息 | 平台规格不同 | 公众号 900×383（2.35:1）、方版 900×900、视频号 **1080×1260（6:7）**；核心内容放中间，四周留安全边距 |

### 内容组

| # | 现象 | 原因 | 怎么办 |
|---|---|---|---|
| 17 | 原录屏音轨 `mean_volume −63 dB`，等于静音 | 录制时没开麦 | 重新配音；**按句配音、按配音时长裁／冻帧对齐画面**，才不会口播和画面错拍 |
| 18 | 白字字幕压在白色幻灯片上看不清 | 对比度不足 | 加半透明黑底框（ASS `BorderStyle=3`），抽帧复检 |
| 19 | 解说词写「插件能自动吸附到顶点」，但代码只吸附图形中心 | 文案先写、代码没核 | `core.js` 的吸附目标只有「中心十字 + 图形中心」，**没有顶点级吸附**。改成「节点吸附能帮上忙」，并在交付时说明这属于 WPS 原生行为 |
| 20 | 自动生成的配图被当成软件实拍 | HTML 画的示意图太像界面 | 图上标注「示意图 · 非软件实拍」，另附**截图清单**让真人在软件里补拍 |

## 五、能力边界与红线

| 能做 | 不能做 |
|---|---|
| 让 AI 写出可安装的加载项、自检脚本、安装文档 | 替你判断这个功能在课堂上到底值不值得做 |
| 一条命令跑完 107 项逻辑自检 | 保证所有 WPS 版本都能跑（版本差异必须真机验） |
| 生成文章、配图、封面、配音与字幕视频 | 生成「真实软件界面截图」（要人在软件里截） |
| 自动排版并校验平台合规 | 绕过安全策略、跳过公开发布确认 |

**与全书三条底线的对应：**

1. **学生数据不出本机**——本例只处理课件文件，全程未涉及学生姓名、成绩、作文等材料。若工具要处理学生数据，优先本地批量，不上传原件。
2. **凡是需要「判断」的位置留给人**——功能好不好用、解说词准不准、图能不能代表真实界面，都要教师自己验；「自检全绿」只说明逻辑通过，不等于课堂效果好。
3. **效果数据不要挪用**——「107 项通过」「51.29 秒成片」都是本次本机实测，只描述这次，不 extrapolate 成普遍结论。

**工具开发专属的两条新红线：**

4. **安全策略拦截不许绕过**：COM 被拦就换一条不碰 COM 的路，不许换个工具硬闯。
5. **公开发布先确认**：发文章、开源、推仓库，一律先报告改动内容、等人点头。

## 七、换个痛点，只改哪几处（给教研组的迁移清单）

| 要改 | 不用改 |
|---|---|
| ① 那句可验证需求 | 六阶段流程 |

三个可以照着搬的学科例子，每个都先写「验收动作」：

| 学科 | 想做的事 | 验收动作 |
|---|---|---|
| 数学 | 给一批几何图形自动标上顶点字母 | 选中 10 个图形点一下，字母按逆时针落在顶点且不重叠 |

> **还是那句话**：先写验收动作，再让 AI 动手。写不出来，说明这件事还没想清楚。
