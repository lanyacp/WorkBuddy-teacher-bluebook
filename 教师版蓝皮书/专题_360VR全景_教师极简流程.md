# 360° 全景互动网页 · 教师极简流程

> 本文件面向一线教师。与完整版的关系：《专题_360VR全景互动网页.md》完整版讲原理与设计规则（给培训讲师/教研组长）；本文件是**教师极简流程**（推荐大多数老师用）。核心原则：步骤一步不少，老师动手压到最少；**生图环节保留老师挑图**（AI 生图有随机性，不合适的图直接毁掉沉浸感，老师肉眼把关）。

---

## 全程只有 6 步，老师真正动手的只有「挑图」这一件技术活

| 步骤 | 老师做什么 | 用时 | WorkBuddy 做什么 |
|---|---|---|---|
| **1 报课题** | 复制启动词（四个槽位），改成自己的课文 | 1 分钟 | 按教材课标分析，先出结构方案，再写每张图的生图提示词 |
| **2 生图挑图** | 把提示词复制到即梦/豆包生图，挑满意的图存好 | 20-30 分钟 | 提供提示词、文件夹、文件名对照表 |
| **3 说一声生成** | 说"图好了，生成网页"（可顺带要结课五页签） | 1 句话 | 生成互动网页，本地预览 |
| **4 说修改** | 说"效果"不说术语（"我想让它判思维"） | 几轮对话 | 按效果改，定位是它的事 |
| **5 发布前自测** | 自己走一遍全流程（30 秒），或让它自动跑 | 30 秒 | 自动测试全流程并报告 |
| **6 要链接** | 说"发布成链接" | 1 句话 | 部署上线，链接发班级群 |

**全程不需要**：写代码、装软件、敲命令行、找全景相机。**全程不省略**：设计方案确认、老师挑图、发布前自测——这三步是效果的保证。

## 第 1 步　报课题：复制这段话给 WorkBuddy

```
我要做 360° 全景互动网页（单文件 HTML，双击文件夹里的 index 就能跑，不装任何环境）。
课文/知识点：【《题西林壁》，五年级语文上册】
教学目标：【让学生从不同角度观察庐山，理解"横看成岭侧成峰"】
学段：【五年级】
请按教材和课标分析，先给我场景和交互的结构方案（先要结构，画面后面再加），
方案确认后为每个场景写好生图提示词，我把图生好后再让你生成网页。
```

> **这段启动词的四个槽位**（缺一个效果就打折，来自一线实测经验）：
> **是什么**（360 全景互动网页，单文件 HTML）· **给谁用**（五年级学生）· **长什么样**（教学目标决定场景）· **怎么跑**（本地文件夹预览，发班级群用链接）。
> 特别提醒：**"单文件 HTML"这句必须说**——不说它可能给你一个要装环境的工程文件夹，发到班里光装环境就劝退一半学生。

**WorkBuddy 会返回三样东西：**

1. **场景方案**：几个场景、每个场景看什么、热点怎么摆（点哪里、弹什么）
2. **生图提示词清单**：每个场景一条，复制就能用，不用你改一个字
3. **图片任务单**：文件夹路径 + 每张图的文件名（比如 `scene1_front.jpg`）

**你要做的**：看一眼方案。觉得行就说"可以"，觉得不行直接说——"第三个场景换成山顶俯瞰""场景太多了，做三个就行"。**方案定了再进第 2 步。**

## 第 2 步　生图挑图（唯一需要你亲手做的环节）

**为什么这步留给你**：AI 生图有随机性，画面不对、风格不对、构图不对，网页做得再好也白搭。你用肉眼挑图，是最可靠的质量把关。

**怎么做：**

1. 打开**即梦**或**豆包**（手机 App 或网页版都行）
2. 复制 WorkBuddy 给的**第一条提示词** → 粘贴 → 生成
3. 挑一张最满意的 → 按图片任务单上的**文件名**保存到指定文件夹
4. 换下一条提示词，重复，直到全部生完

**三条经验：**

| 情况 | 怎么办 |
|---|---|
| 生成的图都不满意 | 不用改提示词，**再点几次生成**，多出几张挑最好的 |
| 想换风格 | 回到第 1 步说"风格换成水墨插画"，WorkBuddy 重发提示词（风格必须整课统一，别一张一个风格） |
| 挑图没把握 | 优先挑：构图对（全景是横长条）> 风格统一 > 细节精致。细节后期可以让 WorkBuddy 换图 |

**存图注意：**

- 全景图是**横长条**（宽是高的 2 倍），别用竖图或方图
- 文件名照抄任务单，一个字都不要改（网页靠文件名找图）
- 放到 WorkBuddy 指定的文件夹里（它会先把文件夹建好给你）

---

## 第 3 步　说一声，生成网页

```
图都放好了，在【D:\我的VR\assets】里，生成网页。
```

WorkBuddy 读取图片、生成完整互动网页、打开预览。你在预览里拖着转一圈，点一点热点。

**可选增强：加一个「结课」页（强烈建议）。** 只有漫游和讲解的课件，课上完就散了。跟 WorkBuddy 说一句：

```
加一个"结课"页，漫游结束后可以点开，里面放五个页签：
总结（把几个场景的知识串成一条线，给学生看）、
作业（分 A/B/C 三层，A 层全班必做）、
教师端（45 分钟课时安排、教学目标、关键提问）、
学生端（任务单自动打勾、自评清单）、
学情分析（总用时、进到哪个场景、点了多少次讲解，加一句诊断）。
```

这五个页签对应五种人：学生自己、课后、上课老师、教研组、想看效果的家长。**少一个，课件就少一个使用场景**——这也是"课件能不能上第二次"的分水岭。

---

## 第 4 步　说修改（把「教学意图」翻译成「效果描述」）

**核心心法：不说"加个练习"，要说"你想要学生在屏幕前发生什么"。** 说得越像效果，它做得越准。

| 你心里的教学意图 | 别这么说 ❌ | 要这么说 ✓ |
|---|---|---|
| 防止学生抄答案 | "加个练习" | "填空能抄，我想让它判思维——改成拖拽拼图" |
| 标题要有课件的味 | "美化一下" | "标题要有笔锋，像毛笔写的" |
| 想知道学生卡在哪 | "加个数据页" | "老师想知道学生进到哪个场景、点了几次讲解" |
| 画面卡顿 | （不用管原因） | "画面会闪黑/卡，你打开截图试到不闪为止" |
| 热点上的字太多 | （同左） | "热点文字压到 20 字以内" |
| 讲解太难懂 | （同左） | "讲解改成三年级能听懂的话" |
| 某张图不合适 | （同左） | "第二张图换一张，我重新生" |

**定位问题是它的事**——你只需要说清"哪一块、什么时候、什么现象"。不用懂图层、字体、显卡，说人话就行。

## 第 5 步　发布前，自己先走一遍（30 秒的事，别省）

**为什么要走**：你的电脑没问题 ≠ 学生的设备没问题。字体、性能、交互，最容易"在你机器上好好的，到学生手机上就出事"。

**让 WorkBuddy 自动跑，或你自己点一遍：**

- [ ] 打开页面，每个场景都进去转一圈
- [ ] 每个热点都点一遍（讲解能弹、配图能看、传送能走）
- [ ] 返回按钮能连续后退
- [ ] 有结课页的：五个页签都点开看
- [ ] 手机上打开试一次（同学段学生用什么设备，就用什么测）

跑通、没报错，才进下一步。

---

## 第 6 步　要链接，发出去

```
发布成链接，我要发到班级群。
```

手机、电脑、平板都能直接打开。以后想改，回来说要改什么，改完重新发布，还是同一条链接。

**课堂上稳妥的做法**：3D 画面吃显卡，机房老机器可能卡。上课时优先**教师机投屏**带着全班走，学生自己探索环节再用手机。

## 一键流程（可选）：全程在 WorkBuddy 里完成

不想自己生图，就用这段启动词：

```
图片不用我挑，你直接 AI 生成并做好网页。做完把每张图发给我确认，
不合适的重新生成，我说可以了再定稿。
```

**但有一条不能省：图片必须你确认后再定稿。** 让 AI 一口气做完直接发布，十有八九要在群里翻车。流程变成：WorkBuddy 自动生图 → **你看图（不合格重生成，一句话的事）** → 定稿 → 发布。省的是复制粘贴，不省的是你的眼睛。

## 附 1　场景与交互设计规则（WorkBuddy 遵守，透明给你看）

| 项 | 规则 | 为什么 |
|---|---|---|
| 场景数量 | 每课 2-4 个 | 少而深，学生记得住 |
| 场景顺序 | 按课文空间顺序或知识递进 | 顺着课文走，不做无主题漫游 |
| 热点分三类 | 导航点 1-2 个（传送下一场景）、讲解点 2-4 个（弹知识卡）、观察点 1-2 个（弹细节图） | 各司其职，学生一眼懂哪个能点 |
| 热点数量 | 每场景 3-7 个封顶 | 超过 7 个就没人点了 |
| 热点内容 | 标题 ≤10 字；说明 ≤50 字；配图可选；一个动作 | 课堂上没时间读小作文 |
| 知识准确性 | 说明里的数字、定义只来自教材，不编造 | 面向学生的内容不能错 |
| 风格 | 一节课一个风格块（写实/水墨/绘本/渲染 四选一） | 一图一画风会出戏 |
| 画面文字 | 生成的图里**不出现文字**（防乱码），文字全放在热点卡片里 | 生图模型画中文必乱码 |

## 附 2　生图提示词规则（五槽公式，WorkBuddy 自动拼好）

每条提示词由五个槽位拼成，你不用自己写，看懂是为了会挑图：

```
任务声明 + 投影格式 + 场景主体 + 风格块 + 负面清单
```

| 槽位 | 写什么 | 例子 |
|---|---|---|
| 任务声明 | 让 AI 知道这是全景素材 | "生成一张等矩形投影的 360° 全景图" |
| 投影格式 | 全景=2:1 长条；特写=4:3 | "宽高比 2:1，左右边缘无缝首尾相接" |
| 场景主体 | 站在哪、看到什么 | "站在庐山脚下正面仰望，群峰连绵，云雾缭绕" |
| 风格块 | 四选一，全课统一 | "风格：水墨插画，留白构图，淡青色调" |
| 负面清单 | 不许出现的东西 | "无文字、无水印、无人物、无扭曲变形" |

**一条现成的例子**（挑图时对照看五槽都在）：

> 生成一张等矩形（equirectangular）投影的 360° 全景图，适合作为网页全景查看器的素材。场景：站在庐山脚下远处正面仰望整座山脉，群峰连绵，云雾缭绕，晨光初照。风格：水墨插画，留白构图，淡青色调，写意山石。画面是完整 360°×180° 球面展开，宽高比 2:1，左右边缘无缝首尾相接；天顶是天空，天底是地面。无拼接缝、无扭曲变形、无文字、无水印、无人物。

**特写图**（热点弹层配图）多一个构图槽：

> 生成一张水墨插画特写图，用于课文热点讲解卡。主体：石松从岩缝中斜生，枝干遒劲。构图：主体占画面 60% 以上，横构图 4:3。无文字、无水印、无人物。

把下面这段设为你的"启动词"，每次只改课题部分，规则不用重复交代：

```

一、我只提供：课文/知识点、教学目标、学段。你负责其余全部。
二、产出必须是单文件 HTML（双击就能跑，不装任何环境）。先给结构方案，确认后再要画面。
三、设计规则：每课 2-4 个场景，按课文空间顺序或知识递进排列。
   热点分三类：导航 1-2 个（传送）、讲解 2-4 个（知识卡）、观察 1-2 个（细节图），

六、修改阶段我只说效果，你负责定位和修复，修完自动跑一遍全流程再交给我。
   最后一步一键发布成链接。

本次课题：【《题西林壁》，五年级语文上册】
```

## 附 4　老师最常问的问题

| 问题 | 答案 |
|---|---|
| 要买 VR 眼镜吗？ | 不用。手机拖着看就是标准用法 |
| 学生家里没电脑能看吗？ | 能。链接手机就能打开 |
| 要买全景相机吗？ | 不需要。即梦/豆包生图是默认路线；学校有真全景照片更好 |
| 生图要付费吗？ | 即梦/豆包每天有免费额度，一节课的图通常免费额度就够 |
| 挑图要用电脑吗？ | 手机就行。生完图发到电脑上存进文件夹，或直接手机传给 WorkBuddy |
| 机房电脑老，会不会卡？ | 3D 画面吃显卡。上课稳妥做法：教师机投屏带全班走，学生自探环节再用手机 |
| 特殊字体换了电脑会变吗？ | 会。你电脑上的字体学生手机上未必有——让 WorkBuddy 把字体做成"子集"嵌进网页里（只打包课件用到的那几百个字） |
| 这个网页会收集学生信息吗？ | 不会。纯展示网页，学生不用登录、不填任何个人信息 |
| 发出去以后还能改吗？ | 能。回来继续说，改完重新发布，还是同一条链接 |

## 附 5　想让课件"能上第二次"？三条方法（融合课/常态课通用）

很多课件的问题是：壳漂亮，课上完就散——没作业、没教案、没有能回收的数据。三条方法：

**1. 找共同问题，不要找共同素材。** 素材是背景板，问题是接口。比如《桃花源记》×编程课的共同问题是"进，还是不进，由什么决定"——语文出条件和动机，编程出判断写法。

**2. 一个真问题，两个接口，一个壳。** 45 分钟塞不下两门完整体系。壳不动、接口换，下节课还能用：

| 学科 | 它能出的"接口" |
|---|---|
| 语文 | 文本里的条件、人物的动机 |
| 历史 | 条约签不签、改革抓不抓时机 |
| 地理 | 工厂选址先看哪一条 |
| 化学 | 为什么必须先 A 后 B（顺序就是判断） |
| 数学 | 分类讨论按什么分 |

**3. 把"后半程"当成课件的一部分。** 课件再漂亮也只是前 30 分钟。作业有没有梯度、老师有没有脚本、学生能不能自查、数据能不能被看见——第 3 步那个「结课」五页签就是为这四件事准备的。

**两点清醒**（数据与 AI 的边界）：
- 学情数据是行为不是理解——点了三次提示可能是真不会，也可能在试按钮。数据给方向，结论你自己下
- 判不了"为什么错"——它知道第三行放错了，不知道学生是没懂"否则"配哪个"如果"。这个得你看他的草稿
