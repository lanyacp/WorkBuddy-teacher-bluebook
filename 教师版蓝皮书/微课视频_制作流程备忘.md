# 微课视频制作流程备忘（配音驱动时间轴法）

> **用途**：知识讲解类微课视频的标准制作流程。**先记下来，后续制作微课视频时按此执行。**
> 记录日期：2026-10-27。本流程已在两个完整案例上实测跑通，成片与全部可复用件见
> `教师版蓝皮书/microcourse/`（本仓库，工具链本机已装齐）。
>
> 与《专题_MG动画与代码生成视频》的关系：MG 专题讲"课堂投屏的交互式网页动画"，
> 本流程是它的**成片化升级**——同样的 Canvas 动画思路，加上配音、逐帧渲染、编码混流，
> 产出可直接发布的 MP4 微课。核心增量：**时间轴由配音驱动 + 动画是时间的纯函数 + 全流程质检**。

---

## 一、核心思想（三条，决定整套做法）

1. **时间轴由配音驱动，不是先定时长再配音。** 先有解说词和逐句配音，量出每句真实时长，再排时间轴、写动画。顺序不能颠倒。
2. **动画必须是时间的纯函数**：`renderFrame(t)` 只依赖 t，不依赖上一帧状态。因此可任意跳帧、可重跑、可并行、画面 100% 确定——录屏做不到（掉帧整段作废且无法定位）。
3. **改一版重出一次的成本只有两分钟，全本地渲染，零第三方费用，不限次数。**

## 二、整套流程（十个节点、四个脚本）

```
选题 → 写解说词 → 逐句配音 → 量时长排时间轴 → 写动画 → 预览关键帧
     → 全量渲染 → 拼接音轨 → 编码混流 → 抽帧质检
```

## 四、制作步骤

**第 1 步 写解说词**——就是写文案，遵守一条约束：**一句话能干完一件事**。勾股定理 8 句、拉马努金 13 句，每句 3–7 秒。

**第 2 步 逐句配音**：

```bash
python -m edge_tts --text "看这个直角三角形，三条边分别是三、四、五。" \
  --voice zh-CN-YunxiaNeural --rate=+12% --write-media audio/l1.mp3
```

音色 `zh-CN-YunxiaNeural`（少年音，清澈）。**语速必须逐句轮换（+12/+14/+16/+18），四句一循环**——全用同一语速听着像念经（实测结论）。

**第 3 步 量时长排时间轴（决定全片质量）**。本机 ffmpeg 没附带 ffprobe，用 ffmpeg 自己解析：

```bash
ffmpeg -nostdin -hide_banner -i audio/l1.mp3 2>&1 | grep -oE 'Duration: [0-9:.]+'
```

拿到每句真实时长后，按「起点 + 时长 + 0.25 秒气口」累加成时间表。**这张表同时写进动画代码的 TL 常量和音频拼接的 concat.txt，两边必须一致**（勾股片总长 37.12 秒，音轨精确 37.12，无漂移）。

**第 4 步 写动画（核心）**。唯一铁律——纯函数：

```js
function renderFrame(t) {          // 只依赖 t，不依赖上一帧状态
  ctx.clearRect(0, 0, W, H);
  drawBg();
  const p1 = prog(t, 's1');        // 每幕的进度 0→1
  ...
}
```

**第 5 步 预览关键帧（省时间窍门）**：渲染器加 `--preview` 模式，只渲染每句的关键时刻。改一次画面几秒钟看结果，不要动辄全量渲染 2000 帧。

**第 6 步 全量渲染**：

```js
for (let i = 0; i < total; i++) {
  await page.evaluate(t => window.renderFrame(t), i / fps);
  await page.screenshot({ path: `frames/f${String(i).padStart(5,'0')}.jpg`, type: 'jpeg', quality: 94 });
}
```

实测：1114 帧 62 秒；2299 帧 128 秒。

**第 7 步 拼音轨 + 编码混流**：

```bash
# 静音段 + 逐句语音交替拼接（concat 列表里的路径是相对列表文件自身解析的）
ffmpeg -f concat -safe 0 -i concat.txt -c copy audio/full.wav
# 帧序列 + 音轨
ffmpeg -framerate 30 -i frames/f%05d.jpg -i audio/full.wav \
  -c:v libx264 -preset medium -crf 20 -pix_fmt yuv420p -c:a aac -b:a 128k -shortest out.mp4
```

**第 8 步 抽帧质检（必须做）**：均匀抽 24 帧拼联系表 + 亮度/方差检测找黑帧；**再从成片 MP4 里抽一次**——编码后的画面要和渲染时核对，不能只看渲染结果。

## 五、踩坑清单（六条，只看代码发现不了）

1. **源元素"没有搬空"**：格子飞走后填充和格线还在，像复制不像搬走。解法：加 drain 参数，填充逐渐褪去、轮廓转虚线。
2. **尺寸标注标进图形内部**：法线方向算反。解法：判断偏移方向；压在别的图形上时文字加白色描边 `strokeText`。
3. **竖式上下行不对齐**：`textAlign:'center'` 遇到行长不同就歪。解法：算符列和数值列各自 right 对齐到固定锚点。
4. **画面比配音慢半拍（最多发）**：动画阈值设在 0.5 以后而配音早说完。解法：**元素出现时间对齐"这句话说到那个词"的时刻，阈值一般不超过 0.4**。
5. **大数字带单位错位**：数字从 42 涨到 190,569,292 时固定位置的"种"会错。解法：`measureText` 量宽，单位跟着移动。
6. **素材假**：随机符号拼"公式"像乱码。解法：用真实式子（∑1/n²=π²/6、∫xⁿ⁻¹e⁻ˣdx=Γ(n)、费马大定理）。**教学材料里假的东西一眼被看出来。**
